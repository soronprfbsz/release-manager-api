# 임시 비밀번호는 화면 1회 표시 후 운영자가 대역 전달한다 (이메일 미도입)

비밀번호 초기화 시 생성되는 임시 비밀번호를 어떻게 대상자에게 전달할지 결정해야 했다. 프로젝트에 이메일 발송 인프라(JavaMailSender/SMTP)가 전혀 없어, 이메일 자동 발송을 택하면 SMTP 설정·템플릿·발송 실패 처리까지 상당한 부수 작업이 따른다.

**결정**: 초기화 응답으로 평문 임시비번을 **1회만** 반환하고, 운영자 화면 모달에 표시(+복사 버튼)하여 운영자가 대상 User에게 **대역(out-of-band)으로 직접 전달**한다. 평문은 어디에도 저장하지 않는다(BCrypt 해시만 저장).

## Considered Options
- **이메일 자동 발송**: 사용자 경험은 낫지만 인프라 구축이 선행되어야 하고 본 기능 범위를 크게 넘는다. → 후속 과제로 분리.
- **화면 표시 + 대역 전달**(채택): 인프라 0, 즉시 가능. 사내 운영자-담당자 관계라 대역 전달이 현실적.

## Consequences
- 운영자가 평문을 보게 되는 노출 창이 생긴다 → [ADR-0002](0002-forced-change-on-reset.md)의 최초 로그인 강제 변경으로 위험 창을 닫는다.
- 임시비번이 응답 본문에 실리므로 요청 로깅(api_log 등)에 본문이 남지 않도록 마스킹을 확인해야 한다.
- 추후 이메일 인프라가 생기면 전달 채널만 추가하면 된다(생성/강제변경 로직은 불변).
