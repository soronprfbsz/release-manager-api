# 초기화된 임시 비밀번호는 최초 로그인 시 강제 변경한다

비밀번호 초기화는 운영자(및 전달 경로)가 임시 비밀번호 평문을 보게 되므로([ADR-0001](0001-temp-password-display-and-relay.md)), 임시값이 대상자의 영구 비밀번호로 남으면 본인 외 인물이 자격을 아는 상태가 지속된다.

**결정**: 초기화 시 `account.must_change_password` 플래그를 set 하고, 해당 계정이 임시비번으로 로그인하면 **변경 완료 전까지 앱 사용을 차단하는 강제 변경 게이트**를 통과해야 한다. 변경(현재=임시 비번 검증) 성공 시 플래그를 해제한다. NIST SP 800-63B의 "관리자 설정 비밀번호는 임시로 취급" 권고에 정렬한다.

## Considered Options
- **미강제(안내만)**: 구현이 가볍지만 임시값이 그대로 영구 비번이 될 수 있어 노출 위험이 지속.
- **비차단 배너 유도**: 사용자가 무시 가능 → 보장 안 됨.
- **차단형 강제 변경**(채택): 위험 창을 확실히 닫음. 대신 스키마 플래그·로그인 응답 확장·차단 게이트 UI가 추가됨.

## Consequences
- `account` 테이블에 `must_change_password` 컬럼 추가(Flyway V19) — 되돌리려면 스키마/로그인 흐름을 함께 되돌려야 함.
- 로그인 응답·`GET /me`에 `mustChangePassword`를 노출해야 하며, 프론트에 전역 차단 게이트가 필요.
- 자가 변경 엔드포인트가 강제변경 게이트에서 재사용된다(현재 비번 = 임시 비번).
